What is Unix time?

Unix time, also called epoch time or a Unix timestamp, counts the seconds since 1 January 1970 at 00:00:00 UTC. It is common in APIs, database records, log files and software.

Unix time is independent of your local time zone. The same instant can display differently in different places. Some systems store milliseconds, microseconds or nanoseconds instead of seconds; selecting the correct precision prevents incorrect dates.

Unix time in programming languages

Practical examples to get the current timestamp or convert Unix seconds to a date.

JavaScript
const seconds = Math.floor(Date.now() / 1000);
const iso = new Date(seconds * 1000).toISOString();
Python
import datetime
now = int(datetime.datetime.now(datetime.timezone.utc).timestamp())
date = datetime.datetime.fromtimestamp(now, datetime.timezone.utc)
PostgreSQL
SELECT EXTRACT(EPOCH FROM NOW());
SELECT TO_TIMESTAMP(1735689600);
MySQL
SELECT UNIX_TIMESTAMP();
SELECT FROM_UNIXTIME(1735689600);
PHP
$seconds = time();
$iso = gmdate('c', $seconds);

Frequently asked questions

Is Unix time the same as epoch time?

Usually yes. The Unix epoch is the starting instant, 1970-01-01 00:00:00 UTC. A Unix timestamp counts seconds or a finer unit relative to that instant.

Why does my timestamp have 10, 13, 16 or 19 digits?

Modern timestamps are often 10 digits in seconds, 13 in milliseconds, 16 in microseconds and 19 in nanoseconds. Historical dates and extreme values can have different lengths, so choose a unit explicitly when in doubt.

Does a Unix timestamp include a time zone?

No. It refers to an instant. A time zone only affects how that instant is displayed as a clock time. Choose UTC or another listed zone above.

What happens before 1970 or after 2038?

Negative timestamps represent instants before 1970. Some older systems using signed 32-bit seconds overflow in January 2038, but modern formats can support later dates. Browser date ranges still have limits.
