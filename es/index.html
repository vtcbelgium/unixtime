¿Qué es el tiempo Unix?

El tiempo Unix o tiempo epoch cuenta los segundos desde el 1 de enero de 1970 a las 00:00:00 UTC. Se utiliza en API, bases de datos y registros de aplicaciones.

Un timestamp Unix es independiente de la zona horaria. Un mismo instante se muestra con horas distintas en diferentes lugares. Algunos sistemas usan milisegundos, microsegundos o nanosegundos en lugar de segundos.

Tiempo Unix en lenguajes de programación

Ejemplos para obtener el timestamp actual o convertir segundos Unix en una fecha.

Tiempo Unix en Python
import datetime
now = int(datetime.datetime.now(datetime.timezone.utc).timestamp())
date = datetime.datetime.fromtimestamp(now, datetime.timezone.utc)
Tiempo Unix en JavaScript
const seconds = Math.floor(Date.now() / 1000);
const iso = new Date(seconds * 1000).toISOString();
Tiempo Unix en PHP
$seconds = time();
$iso = gmdate('c', $seconds);
Tiempo Unix en PostgreSQL
SELECT EXTRACT(EPOCH FROM NOW());
SELECT TO_TIMESTAMP(1735689600);
Tiempo Unix en MySQL
SELECT UNIX_TIMESTAMP();
SELECT FROM_UNIXTIME(1735689600);

Preguntas frecuentes

¿El tiempo Unix es lo mismo que el tiempo epoch?

Normalmente sí. La época Unix comienza el 1 de enero de 1970 a las 00:00:00 UTC. El timestamp indica el tiempo transcurrido desde ese instante.

¿Por qué mi timestamp tiene 10, 13, 16 o 19 dígitos?

Los timestamps actuales suelen tener 10 dígitos en segundos, 13 en milisegundos, 16 en microsegundos y 19 en nanosegundos. Los valores antiguos pueden ser más cortos; selecciona entonces la unidad.

¿Incluye un timestamp Unix una zona horaria?

No. Identifica un instante. La zona horaria solo cambia cómo se presenta la hora local. Elige UTC u otra zona arriba.

¿Qué ocurre antes de 1970 o después de 2038?

Los timestamps negativos indican fechas anteriores a 1970. Algunos sistemas antiguos de 32 bits se desbordan en enero de 2038; los formatos modernos pueden ir más allá.
