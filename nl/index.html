Wat is Unix-tijd?

Unix-tijd, ook epochtijd genoemd, telt het aantal seconden sinds 1 januari 1970 om 00:00:00 UTC. Software gebruikt dit formaat in API's, databanken en logbestanden.

Een Unix timestamp is niet gebonden aan jouw tijdzone. Hetzelfde moment wordt wereldwijd anders weergegeven. Sommige systemen slaan milliseconden, microseconden of nanoseconden op in plaats van seconden.

Unix-tijd in programmeertalen

Voorbeelden om de huidige timestamp op te halen of seconden om te rekenen naar een datum.

Unix-tijd in Python
import datetime
now = int(datetime.datetime.now(datetime.timezone.utc).timestamp())
date = datetime.datetime.fromtimestamp(now, datetime.timezone.utc)
Unix-tijd in JavaScript
const seconds = Math.floor(Date.now() / 1000);
const iso = new Date(seconds * 1000).toISOString();
Unix-tijd in PHP
$seconds = time();
$iso = gmdate('c', $seconds);
Unix-tijd in PostgreSQL
SELECT EXTRACT(EPOCH FROM NOW());
SELECT TO_TIMESTAMP(1735689600);
Unix-tijd in MySQL
SELECT UNIX_TIMESTAMP();
SELECT FROM_UNIXTIME(1735689600);

Veelgestelde vragen

Zijn Unix-tijd en epochtijd hetzelfde?

In de praktijk wel. De Unix-epoch is het startmoment: 1 januari 1970 om 00:00:00 UTC. Een Unix timestamp telt de tijd vanaf dat moment.

Waarom heeft mijn timestamp 10, 13, 16 of 19 cijfers?

Huidige timestamps hebben vaak 10 cijfers in seconden, 13 in milliseconden, 16 in microseconden en 19 in nanoseconden. Bij oudere datums kan de lengte verschillen. Kies dan de eenheid zelf.

Bevat een Unix timestamp een tijdzone?

Nee. De timestamp verwijst naar een tijdstip. Een tijdzone bepaalt alleen de weergave op de klok. Kies hierboven UTC of een andere tijdzone.

Wat gebeurt er vóór 1970 of na 2038?

Negatieve timestamps betekenen een moment vóór 1970. Oudere 32-bit systemen kunnen in januari 2038 vastlopen. Moderne systemen ondersteunen doorgaans latere datums, binnen hun eigen grenzen.
